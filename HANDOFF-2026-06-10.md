## 6) DÉMO SOUTENANCE
- **Incident applicatif (gagnant, sûr)** : `kubectl -n pfe patch deployment podinfo --type=json -p='[{"op":"add","path":"/spec/template/spec/containers/0/command","value":["/bin/sh","-c","echo boom; exit 1"]}]'` → POD_CRASH_LOOP détecté → décision IA → Camunda remédie (auto) → résolution. Restaurer : `... -p='[{"op":"remove","path":"/spec/template/spec/containers/0/command"}]'`.
- **Mauvaise image (approbation humaine)** : `kubectl -n pfe set image deployment/podinfo podinfo=stefanprodan/podinfo:6.7.0-cassee` → DEPLOYMENT_UNAVAILABLE → tâche humaine (tu approuves dans l'UI). Restaurer : `...:6.7.0`.
- **Node-down** : le power-off VMware d'un worker survit maintenant (UI/API/DB OK, NODE_NOT_READY détecté + auto-résolu au retour). **Méthode sûre alternative** : `ssh kube@<worker> "echo kube | sudo -S systemctl stop kubelet"` puis `start`. **Couper worker2** = scénario où tout survit (le primaire DB y est mais bascule).
