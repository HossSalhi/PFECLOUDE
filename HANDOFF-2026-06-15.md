## ⚠️ GOTCHAS (pièges rencontrés)
- **podinfo n'a AUCUNE sonde par défaut** → `/readyz/disable` seul ne le rend pas NotReady. La démo réparable AJOUTE une readinessProbe sur `/readyz` (fait dans casser-podinfo.ps1, idempotent).
- **PowerShell + kubectl JSON** : un patch `-p '{...}'` inline est mal parsé par Windows → utiliser `--patch-file <fichier>`. Le port-forward via `Start-Job` est flaky → remplacé par `Start-Process` + `Test-NetConnection` (attente du port). Scripts corrigés.
- **Incidents orphelins** : si on supprime une app pendant que son incident est actif, il peut rester IN_PROGRESS (plus revisité par le polling car plus découvert). Fermeture manuelle = `update incident set status='RESOLVED' where app like 'incident-%' and status not in (...)`.
- **LimitRange `pfe-limits`** cap CPU à 500m/conteneur → pour un pod Pending utiliser un `nodeSelector` inexistant, PAS une demande de 100 CPU.
- Images : seul **podinfo (stefanprodan/podinfo:6.7.0)** est en cache (air-gap), busybox NON.
